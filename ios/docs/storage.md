# 本地存储与成功状态

内部 schema v1 使用 SwiftData 的版本化 schema。`Metadata` 保存资料集身份、单调修订与本机运行设置；`Entity` 每行对应一个稳定业务实体，按实体类型和 ID 唯一寻址；`Receipt` 保存成功操作标识。每行的 Codable 负载保存有序照片、动作、训练组和版本历史，避免依赖无序的一对多关系。不是把整份资料作为一个 JSON 文件覆盖。

CloudKit 在磁盘库和演示库中都显式设为 `.none`。正式库持久落盘，演示库只在内存中存在。活动 ModelContext 由 ModelActor 串行使用，关闭 autosave；视图只读取脱离数据库对象的值。

提交顺序：读取已提交值 → 检查预期修订 → 在值副本上修改 → 校验身份和引用 → 暂存各行 → 保存数据库。成功返回只发生在 `save()` 之后。任何保存错误都会 `rollback()` 并向调用方抛出；调用方必须保留编辑值，不显示已保存。提交 ID 由一次用户提交创建，重试沿用，成功收据和数据在同一事务中落盘；重新打开后重复提交不会再创建记录。

未知 schema、损坏实体和引用错误直接失败，不捕获后清库。不要手工复制运行中的 SQLite 单文件（可能遗漏 WAL）。

可在临时目录执行 `swift test`，验证真实 SwiftData 磁盘往返、顺序和空值、写入失败、重试幂等、重新打开、预期修订冲突与演示隔离。测试数据由测试自身构造，不读取个人身体信息或照片。

## 照片生命周期

`preparePhoto` 校验 JPEG／PNG／HEIC 的真实格式、文件大小与像素数，应用方向后重新编码，去掉 EXIF/GPS；原图内容地址位于 `media/<SHA-256>.<ext>`，缩略图位于 `thumbnails/`。先写 `staging/`，再发布稳定文件，最后提交包含图片引用的数据库事务。相册文件删除不影响副本。

新引用必须通过实际文件和摘要校验才能成功提交。文件已写入但数据库失败时，仍由准备中的引用保护，允许重试；明确放弃后释放准备引用。启动清理只在库已成功打开并完成关系校验后运行，保留正式记录、草稿、回收站、任务和导出租约引用的文件。同内容的不同资产 ID 共享文件时，按路径集合保护。单个个人目录只由应用当前的 repository 实例持有，不在多个进程／扩展中并发打开。

导出通过 `acquireSnapshot` 取得不可变值与文件读取租约，结束后必须 `releaseSnapshot`；后续编辑不会更改已取得的值，清理器会保留租约中的图片。孤儿清理不会扫描或修改媒体目录之外的个人文件。

## 升级与恢复

App 使用 `ManagedStore` 管理 `Personal/active.json` 指向的 `stores/<generation>/`。首次创建带 bootstrap 日志；缺失指针但已有资料目录时视为损坏，不当作新安装。未知版本在打开 SwiftData 前被拒绝。

已知版本升级前冻结旧仓储写入，取得包含提交收据的已提交快照与图片租约，构建新的 SwiftData 库并逐张校验复制照片，完整验证后写 `ready.json`，最后原子替换 `active.json`。旧库保持在原目录，`previous.json` 指向升级前版本。升级中断时，启动按原子指针选择完整的旧库或新库，并清理未激活候选目录；不从正在使用的数据库复制 SQLite／WAL 文件。v1 暂无需执行数据转换，恢复重建与以后已知版本的转换共用这条路径。

打开失败时，在 App 选择「恢复上次升级前资料」，阅读确认后切换到验证通过的 `previous.json`；没有旧版本时会明确失败，绝不清库。升级后的目录仍保留。若界面也无法打开，请保留完整应用容器，勿卸载；恢复时须保留同一代目录及其图片，不能单独替换 SQLite 文件。未知新版本不得用旧代码强行打开，先回到保存该版本的 App，再走显式导出恢复。

## 草稿和回收站

`DraftAutosaver` 合并 300 ms 内连续输入，离开表单可 `flush()`；状态区分保存中、最后成功时间和失败，承诺仅覆盖最后成功提交的草稿。失败时保留待写值及同一提交 ID，允许重试。历史编辑草稿不改变正式记录；另一训练草稿不能覆盖已有活动会话。放弃写入不含内容的草稿墓碑，使迟到保存不能复活草稿。

各资料库的建库与迁移在同一工厂 actor 中串行完成，避免底层共享 schema 元数据在并发建表时冲突；已打开资料库仍分别使用自己的仓储 actor。表单输入修订也参与草稿排序，迟到的旧输入不会覆盖新值。

删除按经过的 30×24 小时保留。删除和恢复均递增生命周期代号、清除当天完整确认，删除取消在途任务；恢复不使旧任务重新有效。满期或确认永久删除后保留来源身份墓碑，供旧备份导入时明确识别恢复冲突。仅无记录、草稿、回收站、任务或租约引用的照片才会清理；外部备份不受本机删除控制。
