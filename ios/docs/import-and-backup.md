# 导入、回退和目录备份

## 从原型迁移

1. 保持网页原型的本地服务运行，在原型中打开「我的 → 数据管理 → 导出数据 → 下载原型资料」。必须使用实际下载的版本 1 JSON；它把图片嵌入文件中。
2. iPhone「我的 → 数据管理 → 导入与恢复 → 选择资料包」，选择该 JSON。
3. 查看示例排除数量，确认记录时实际时区及 kg／cm／分钟／kcal 单位，确认未标记为示例的记录是自己的内容。缺少资料生效日时选择日期；无提交时间的历史需明确确认其身份映射。原文件顺序不宜随意重排。
4. 点击「转换并生成导入预览」。照片路径为 `assets/...`、远程地址或无法解码时会拒绝迁移，请回原型重新完整导出。应用不会下载替代图片。
5. 预览默认保留本机。采用导入版本是对本次内容冲突的成组选择；恢复已永久删除的记录、已放弃或已提交的旧草稿需要额外逐项打开恢复开关。最后点击确认导入。

原型示例餐食、带明确虚构样例标记的训练以及 `demo: true` 资料默认排除。`demo-ai` 和无法核实的估算只保留演示历史，不能成为当前真实摄入。人工修正可以保留，并指向原始历史。缺少必要身体参数不生成资料版本；缺少训练消耗参数不按当前体重补算。缺少提交时刻用 Unix 0 表示未知；原型记录的绝对时刻为 null，保留已确认的当地日期、时间和时区。

## 原生包恢复

在同一入口选择完整 `.boji` 包或对应目录。文件若是云端占位内容，先等待系统下载；失败时可在「文件」App 下载全部内容后重试。读取会校验格式、字段、关联、图片解码、文件大小和 SHA-256。上限为 2 GiB 总量、128 MiB JSON、20000 条业务实体、10000 张照片，每张不超过 50 MiB／5000 万像素。

预览之前先复制到应用自己的暂存目录。预览后本机内容改变会要求重新预览，不能用过期结果覆盖正在编辑的资料。相同包重复导入不会增加记录、照片或历史；来源映射会随再次导出保留。合并后的日事实不完整一致时，不沿用「已记全」确认。

导入先创建完整影子库，复制照片并验证，再切换活动库。导入不恢复外部凭据、目录授权、发送授权或在途任务；现有本机 AI 配置可保留，但不会自动识别导入餐食。故障发生在激活之前使用旧库，之后使用完整新库；不会显示半套导入。

「恢复上次导入或升级前资料」须再次确认。请先导出当前资料，避免遗漏导入后新增的记录。回退切换到上次完整库，同时把当前完整库留作再次回退的版本；它不会把两个版本自动合并。不要卸载 App 或手工删除 Application Support。

## 单向目录备份（历史实现，当前 MVP 不开放）

2026-10-24 起，产品导航移除目录备份，自动备份轮询停用。手动导出使用「我的 → 数据管理 → 导出数据」；已有外部文件与本机备份配置不会自动删除。以下记录保留用于理解旧版本行为。

「我的 → 目录备份 → 选择备份目录」，选择自己的 iCloud Drive 或其他目录。薄记只管理 `Boji/<dataset UUID>/`；该目录里的 `owner.json` 标识归属，完整快照使用唯一 `<export UUID>.boji` 名称，`latest.json` 指向最近发布的完整版本并记录 manifest 摘要。

本机提交先成功保存，再标记待备份；连续变更静止至少六秒后，在前台有运行机会时合并发布。可以随时点「立即备份」。失败会保留待备份状态和原完整快照，最多自动尝试三次，间隔 15／60／300 秒；重回前台或手动重试恢复机会。后台被系统暂停时不保证固定完成时间。

「已写入目录」不代表云端已上传。只有最新指针、manifest 和所有数据／照片文件均被系统报告为已上传时，才显示上传确认；状态缺失时显示未知。应用不会声称 Mac 已下载。更换或断开目录不删除旧位置；本机删除也不会撤回既有备份。

Mac 修改最新指针、快照内容或来源，会停止后续发布，保留双方。请先保存有用的外部修改，选择新空目录继续备份；需要恢复的包走导入预览。再次选择已有同资料集目录时，必须能完整校验，才会把该位置作为新的备份起点。未知文件不会被覆盖。

## Mac 读取和空间管理

1. 打开所选目录的 `Boji/<dataset UUID>/latest.json`，根据 `package` 找到快照。
2. 在 Finder 下载整个 `.boji` 包。指针先到达不代表媒体齐全；用 `python3 ios/Scripts/read-package.py /完整路径/xxx.boji` 校验。按 `package-format.md` 检查记录、来源、历史和完整度。
3. 阅读包内 README，复制 `agent-prompt.txt` （当前 App 已移除「导出与 Agent」提示词入口），自行提供给 Agent；App 不会发送消息。
4. 每次备份保留一份完整快照，会占用额外空间。用户可在另有完整副本后自行管理旧包；不要删除 latest 指向的包。App 不自动清理所选目录的历史或未知文件。应用内部生成和导入暂存位于系统 Caches，受系统空间管理；本机正式记录位于 Application Support。

2026-10-18 已使用用户选定的「薄记测试备份」完成真实 iPhone ↔ iCloud Drive ↔ Mac 交付。Mac 初见占位文件，等待系统下载后 `read-package.py` 对 10 个文件及 manifest 校验通过，可读出训练及照片；断开目录后本机记录仍正常保存，原快照仍在，重选目录成功。详见 `verification.md`。
