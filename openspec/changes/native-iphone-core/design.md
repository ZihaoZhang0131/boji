# 原生 iPhone 核心功能设计

## Context

动机与产品范围见 [proposal.md](proposal.md)。目前没有原生工程、服务端或主规格；现有静态网页通过 `app.js → redesign.js → energy.js → pixel.js` 覆盖全局渲染和事件方法，使用 `localStorage` 保存整份 JSON 和图片数据。原型已有公式、部分输入校验及浏览器验证，但无法直接充当原生的数据层。

本设计依据以下实际行为，而非只看页面文案：

- `app.js` 首次启动会装入示例记录、个人资料和固定日期；`persist()` 返回失败后，多个调用方仍继续显示成功。
- `energy.js` 的识别由计时器返回固定样例；已有人工修正和输入变化失效逻辑，但缺少真正持久化的任务、授权与并发控制。
- `redesign.js` 中 iCloud 入口仅转到导出；`openAgent()` 只复制复盘提示词。
- 旧 JSON 导出版本为 1，图片通常为 data URL；测试中有可复用的数值样例与操作意图，不能把浏览器测试通过当作原生验收。
- `energy-spec.html` 关于不自动填入样例资料的文字与当前初始化代码存在差异。原生版以本变更「空资料启动、演示隔离」规格为准。
- 已确认原生 iPhone、个人自用、Mac 文件复盘；本机已有 Xcode 和 iOS SDK。签名身份、设备与供应商配置尚未提供。

## Goals / Non-Goals

**Goals:**

- UI、存储、计算、AI 与资料流转有清晰边界，单项外部服务故障不阻断本地记录。
- 每次成功提示、图表数值和导出均能追溯到已提交的版本，异步结果不得覆盖较新事实。
- 可用确定性测试验证公式、时间、状态机、恢复和迁移，并用真机验证系统能力。

**Non-Goals:**

- 不把网页嵌入 WebView 作为正式核心界面，不照搬其全局函数覆盖结构。
- 不把运行中的数据库文件直接放入 iCloud Drive，也不让外部 Agent 直接编辑活动数据库。
- 不构建多租户平台或通用 Agent 执行系统；功能边界以提案和八份规格为准。

## Decisions

### 1. 原生模块与平台基线

设计默认支持 iOS 17 及以上，使用 SwiftUI 与 SwiftData；以当前可用 Xcode 构建，最低系统版本在工程和验收设备矩阵中显式设置。原生工程放在 `ios/`，已有可选识别服务放在 `services/food-estimation/`，网页保持可用于参考和旧数据导出。

原生分为 App／DesignSystem、Meals、Workouts、Profile、Review、Persistence、Estimation、Portability 模块；领域计算和资料包 DTO 不依赖视图。通过可替换的仓储、时钟、网络、文件访问和模型服务边界进行测试，生产配置不允许静默使用模拟适配器。

```text
SwiftUI screens
      |
Application actions --> Domain rules / Energy calculations
      |
Local repository --> SwiftData + Media files
      |                    |
      |                    +--> Export snapshot --> iCloud Drive --> Mac Agent
      |
Persistent job queue --> Qwen HTTPS endpoint
      ^                       |
      +----- Versioned result +
```

备选：WebView 复用成本低，但不符合已确认的原生路线；UIKit 全量构建可行，但此项目没有 UIKit 历史负担。采用 SwiftUI，拍照和目录选择按需桥接 UIKit。PhotosPicker 负责相册选择，系统相机负责拍摄，不要求全量照片库权限。保留项目字体许可，原生字体资源需从合法源字体构建或取得适合 iOS 的字体格式，不能假设现有网页字体可直接注册。

### 2. 本地库为事实来源，照片独立管理

使用 SwiftData 的版本化 schema 和明确的 repository 提交，写入串行化；表单编辑 DTO 与持久化对象隔离，不依赖隐式 autosave 来判定成功。SwiftData 提供显式保存、回滚和版本迁移能力，采用它以减少个人应用的存储维护代码。[ModelContext](https://developer.apple.com/documentation/swiftdata/modelcontext)、[SchemaMigrationPlan](https://developer.apple.com/documentation/swiftdata/schemamigrationplan)。

| 实体 | 关键内容与约束 |
|---|---|
| Dataset | 稳定资料集 UUID、存储版本、已提交总体修订号 |
| Meal | UUID、事实修订、识别输入修订、生命周期代号、当地日期时间与时区、备注／餐次／标签、有序照片引用、当前估算引用、人工修订号、删除时间 |
| PhotoAsset | UUID、SHA-256、相对路径、格式、大小、尺寸；展示缩略图可再生成 |
| Workout | UUID、日期时间、名称、有序动作和完成组、计算快照历史、删除时间 |
| Draft | 类型、新建或编辑、目标记录 ID、有序表单内容、最后成功保存时间；唯一活动训练会话 |
| ProfileVersion | UUID、生效日期、单调提交序号、身体参数、可选摄入目标、创建时间与来源 |
| GoalStage | UUID、开始／结束日期、目标与备注；同日切换保留提交顺序 |
| DayConfirmation | 当地日期、用户确认时间、对应事实集合修订 |
| DeletionTombstone | 已永久删除记录的来源和稳定 ID、删除时间；不保留原始内容，用于识别旧备份中的恢复冲突 |
| EstimateRevision | 类型、输入修订、食物项与原始克数／热量、总值、假设、模型来源／版本、人工变更和创建时间 |
| EstimateJob | 持久请求 ID、任务 ID、输入与生命周期代号、授权代号、发起时人工修订号、尝试次数、状态与期限 |
| BackupState | 目录书签、最后发布修订、待备份标记、正在生成的导出 ID、最后指针摘要及可观察上传状态 |

照片使用 Application Support 中的独立文件，保留实际画面和方向，去除用于上传／导出的定位元数据，生成单独缩略图；不以 base64 大字符串写入数据库。原生数据库和照片应用系统文件保护，凭据用 Keychain；导出包不包含凭据、目录书签或授权代号。

照片与数据库无法共享一个底层事务，采用以下提交顺序：先暂存并校验图片，再移到稳定内容地址，最后在数据库事务中提交记录与引用。数据库失败则回滚记录并保留可重试草稿；启动清理器仅删除确认无正式记录、草稿、回收站或导出租约引用的孤儿文件。提交成功前不得清除旧图片引用。

草稿在编辑事件后短暂合并写入，失焦或离开表单时请求立即保存；界面区分保存中、已保存和失败。进程随时可能被终止，因此恢复承诺限于最后成功提交的草稿版本。训练编辑草稿不改变原正式记录，最终成功提交后才替换旧版本并更新统计。

删除写入 `deletedAt` 并递增生命周期代号，取消关联任务、清除受影响日期完整确认。回收期按删除时刻经过 30×24 小时计算，清理在应用获得运行机会时执行；恢复不重用旧任务资格。外部已导出备份是独立副本，不声称本机删除能撤回它们。

备选：直接存单个 JSON 难以处理照片规模和事务；自行写 SQLite 可获得更细控制，但当前领域规模适合 SwiftData。CloudKit 自动数据库同步不属于当前文件交付路线，配置显式关闭，避免启用某项 iCloud 能力时意外改变存储行为。[SwiftData 同步配置](https://developer.apple.com/documentation/swiftdata/syncing-model-data-across-a-persons-devices)。

### 3. 时间、资料历史和完整度统一处理

记录保存 `localDate`、`localTime`、`timeZoneIdentifier` 与可确定的事件时间戳，创建／修改审计时间使用 UTC。日期归属以用户确认的当地日期为准，时区切换不重新分桶；同一时刻的列表排序以稳定 ID 兜底。旧资料时区无法确定时明确标记为迁移时确认的时区或未知，不伪造原始精度。

个人资料默认今天生效，按生效日期和提交序号选取版本。新增过去日期的资料时，先计算直到下一个生效版本前的影响区间并确认；只重算日常基线。已完成训练始终引用快照，用户主动重估才新增计算版本。

阶段按 `[startDate, endDate)` 归属；同日多次切换形成可审计的零天旧阶段，最终阶段拥有该日。只改当前备注不新建阶段。开始日期不得倒置历史或超出今天。

所有正式事实变更集中发送受影响日期集合，包括移动记录的旧日和新日，并清除这些日期的已记全确认。纯估算值变动不清除用户确认，但聚合仍检查所有必需估算是否有效。完整统计要求至少一餐，不能把「零条记录」解释为禁食事实。

公式和四舍五入按 `energy-and-review` 规格实现为纯函数；用 Decimal 或等价受控精度处理份量修改，在确定的边界转换显示值。份量按最近一次人工设定的参考克数和热量计算，避免连续改变输入时逐步舍入造成漂移。训练计算缺参数返回可解释的未知原因，不使用隐式零值。

备选：每次用当前资料重算所有历史实现更简单，但会改写训练事实；仅用 UTC 日期又会移动跨时区历史。因此保留当地日期和计算快照。

### 4. 界面复用视觉与交互意图

以现有三项导航和 Sheet 为原生界面地图，设计组件覆盖像素边框、字体、按钮、记录卡、输入行、来源标记、图表图例、空状态与错误状态。普通字号尽量保持现有风格，较大字号改用可重排布局；字体缺字使用系统中文后备，触控区域不受像素视觉尺寸限制。

图表使用原生绘制与可访问数值列表共享聚合输出，不重复实现统计。正式模式不出现固定手机外框、场景控制台或示例自动灌入。演示使用单独的临时库和网络禁用适配器；关闭演示即返回正式库。

相机、文件选择和分享可使用系统视图；选中图片写入本机副本后才脱离系统资源引用。相机失败时保留表单、允许相册和文字路径。系统字号、键盘避让、VoiceOver、浅深色与安全区域纳入真机验收。

### 5. 识别状态与竞争处理

识别以已保存记录为自动触发边界；用户对未完成表单手动识别时，先把当前输入和照片可靠保存为草稿，再以草稿的稳定记录 ID 创建任务。正式保存沿用 ID 和输入修订，避免结果丢失或关联到另一餐。新事实变化递增 `inputRevision`；仅日期／餐次／标签变化不递增。人工确认递增 `manualRevision`。

```text
unconfigured / consentRequired
             |
             v
pendingNetwork --> queued --> running --> ready
      |              |           |        |
      +--> cancelled +--> failed +        +--> stale

manual edit --> manual
```

任务本身只保存排队、运行和终态；未配置、未授权、过期与人工值属于记录展示状态，不能混成一个互相覆盖的字段。结果应用必须同时匹配：资料集、记录 ID、输入修订、生命周期代号、授权代号以及发起时人工修订号。写入前在本地同一提交边界重新核对，删除、恢复、放弃草稿和撤权均使旧资格失效。

离线任务保存不可变输入引用，联网且应用获得执行机会时重新核对资格。每个输入最多一个活动任务；旧输入队列取消。关闭自动估算停止新自动任务并取消尚未发出的自动任务，手动任务仍需有效授权；撤权取消全部未终结任务。直连请求可能已发出后不自动重试；不依赖 iOS 保证后台常驻。

原始 AI 输出通过验证后以结构化历史版本保存；人工调整永远创建新版本而不是修改模型原始输出。重新识别若晚于人工修正返回，只展示可供比较的历史结果；用户明确采用才改变当前值。

备选：只比较照片与备注字符串无法阻止删除后恢复或人工覆盖竞态；采用明确修订号和生命周期代号，使状态转移可测试且跨重启可恢复。

### 6. 个人版直连千问与可选私有服务

个人版默认不部署服务器。iPhone 用固定的千问 HTTPS chat-completions 地址和 qwen3-omni-flash 模型；用户只在手机输入 API Key，密钥保存在不可同步的本机 Keychain，不写入资料库、导出包、日志或代码。端点不接受饮食内容指定，也不跟随重定向。服务目录中已实现的 TypeScript 私有服务及其契约测试保留为可选适配器，但不作为个人版验收条件。

在 AI 设置中展示千问、模型、发送范围、供应商保留政策链接、费用由用户自己的千问账户承担及本机每日尝试上限。用户确认后才允许发送；模型、端点或政策版本变化使授权失效。自动开关与发送授权独立。App 不声称本机上限是金额预算，用户仍应在供应商账户配置金额限制。撤权取消未发出的本机任务；已送达供应商的资料无法追回。

任务和输入版本继续由本机资料库持久化。离线时只排队，不建立网络请求；联网且 App 有执行机会时重新核对资料集、记录、照片、备注、输入修订、生命周期、人工修订和授权。每个输入最多一个活动任务。准备调用时先将尝试状态和时间落盘；一旦网络调用可能已发出，超时、响应丢失、进程终止都记为结果未知，不自动重试。用户主动重试会创建新尝试并提示可能再次计费。跨设备或跨客户端无法由本机保证供应商幂等，不能沿用私有服务的请求 ID 幂等承诺。

输入照片在本机归一化为 JPEG，最多九张，每张最多 2 MiB、总量最多 18 MiB；备注最多 8000 字符。千问官方将 qwen3-omni-flash 列为不支持结构化输出的旧型号，故请求只通过提示要求 JSON，不发送不兼容的 response_format；本机必须逐字段及数值校验，不发第二次模型修复请求。仅接收成功结束的一条可解析为 JSON 的文本输出、真实响应中的模型标识与合法食物项；非有限数值、负值、项目合计不一致、无有效项目、范围不包围合计或超过 10000 kcal 均失败，不能写入当前摄入。照片和备注里的命令是非可信素材，不参与应用指令。来源标为模型估算，范围不冒充统计置信区间。

模型使用用户在千问AI平台密钥页面提供并经官方文档核对的千问AI平台端点；实际请求参数须按该模型官方文档验证。Qwen3-Omni-Flash 的图片输入示例使用流式文本输出，因此客户端解析有上限的流式结果，并拒绝工具调用、音频输出和不完整终止。供应商返回的真实模型 ID 入历史。见千问AI平台官方文档：https://platform.qianwenai.com/docs/developer-guides/getting-started/first-api-call 与 https://www.qianwenai.com/models/qwen3-omni-flash 。旧版 `ap-southeast-1.maas.qwencloudapi.com` 地址下的本机授权在升级后失效，不自动迁移密钥。

已有服务适配器的持久任务、owner 鉴权、上传和任务接口仍按 services/food-estimation/README.md 维护；启用它需要另行部署 HTTPS、配置高熵个人令牌和供应商密钥。此路径不改变个人版直连的默认设置，也不得让 App 在未配置直连时静默使用测试结果。

### 7. 资料包格式与导入事务

定义目录资料包 `.boji`，导出格式 `schema_version: 2`；与数据库内部 schema 版本分开演进。包自包含，Mac 无需薄记 App 即可读取。

```text
<export-id>.boji/
  manifest.json
  records.json
  profiles.json
  goals.json
  estimates.json
  drafts.json
  trash.json
  media/<sha256>.<ext>
  README.md
  agent-prompt.txt
```

`manifest.json` 包含格式版本、`dataset_id`、`export_id`、生成时间、已提交资料修订、单位和时区约定、各实体数量，以及除 manifest 自身外每个文件的相对路径、SHA-256、字节数。照片关联同时包含资产 ID 与包内相对路径。备份包包含回收站和草稿，读取说明要求复盘默认排除；演示数据空间不进入正式导出，旧数据的演示来源标记必须保留。

先取得不可变 DTO 快照及照片读取租约，在临时目录写完所有文件并验证，再最后写入 manifest 和发布完整目录。读取端必须核验 manifest 中所有文件，不能仅凭 manifest 已到达就认定跨设备文件齐全。SHA-256 用于完整性检查，不提供文件来源真实性证明。

导入流程：系统选取资料包 → 下载必要占位文件 → 校验 → 预览 → 冲突选择 → 构建影子资料库 → 验证 → 原子切换活动库指针。构建期间串行化资料写入并暂停结果应用，AI 结果仍可稍后重新核对；不复制处于活动状态的 SQLite 文件或遗漏 WAL。旧库作为可恢复版本保留到新库确认可用。失败只清理暂存，新库未激活则原数据不变。

原生包使用 `dataset_id + entity_type + id` 作为外部身份；首次导入外国资料集建立来源映射，后续导入复用映射。相同内容跳过，不同内容逐项／成组预览选择，默认保留本机；删除状态和恢复也是冲突，不按时间戳直接覆盖。关联实体一起校验，禁止产生悬空照片、资料历史和估算引用。导入的新内容不自动创建 AI 任务；现有本机授权可保留，但不会从外部包恢复授权、任务会话或凭据。

预检默认上限：包总量 2 GiB、结构化数据 128 MiB、20000 条业务记录、10000 张图，单图 50 MiB 且不超过 5000 万像素；预留导入暂存和影子库所需空间。读取分批进行，拒绝绝对路径、`..`、符号链接及逃出包目录的真实路径；无论校验值是否匹配，字段内容始终按不可信数据解析。超过上限明确报告，不无限分配内存。

旧版 JSON 迁移支持实际导出的版本 1：

- 保留餐食／训练原 ID，经固定原型命名空间映射成稳定 UUID，避免每次按整个文件摘要创建新身份。无 ID 的资料历史使用生效日与原提交时间，阶段使用开始日和目标生成稳定身份，结束日期或备注变化进入冲突比较；时间和身份不足以区分的历史在预览中要求确认，不静默制造重复阶段。
- data URL 解码并验证图片，缺失文件引用或外部 URL 阻止完整迁移，不自行联网补图。
- 将 `profile`、`profileHistory`、`plan`、`planHistory`、`complete`、`draft`、餐食 `energy` 和训练计算快照映射到原生实体；缺失单位或时区须在预览确认，未知热量保留未知。
- `demo: true` 项默认排除；用户餐食带 `demo-ai` 时保留原始记录并将估算隔离为演示历史，不让示例值进入真实摄入；无法确认的来源交给导入预览。
- 冲突预览显示排除示例后完整度或目标关联失效的原因；无有效餐食的日期不能继续作为已记全日期。未知字段不无筛选拷入资料库或导出包。

备选：直接导出内部数据库绑定框架版本、难以供 Agent 解释；只导出单个 base64 JSON 不便于查看照片和增量恢复。因此采用可独立解读的 JSON 加媒体文件包。

### 8. iCloud Drive 为单向资料交付

通过系统目录选择器获得 security-scoped URL，保存书签并在每次访问时重新解析；按系统要求开始／结束授权访问和协调写入，处理书签失效及用户撤权。[目录访问](https://developer.apple.com/documentation/uikit/providing-access-to-directories)、[NSFileCoordinator](https://developer.apple.com/documentation/foundation/nsfilecoordinator)。

选定目录下只管理自己的 `Boji/<dataset-id>/` 子目录。每次发布使用唯一快照目录，完整写入后再协调更新 `latest.json`，其中记录导出 ID、资料修订及 manifest 摘要。指针更新前核对上次写入摘要；发现外部更改或冲突则保留双方，报告需要用户处理，不覆盖未知版本。已有快照不原地改写，Mac Agent 仅读取校验完整的快照。

成功的本地资料提交把备份标为 dirty，合并连续编辑后在前台空闲或有限后台执行机会写入，提供「立即备份」。写入失败保留 dirty 和上次成功版本，采用有限重试并在重新前台／授权恢复后继续。默认不自动删除已发布的外部快照；目录空间不足时提示用户管理备份，避免误删其交付历史。

目录写入与云端上传为两个事实。仅在文件提供者提供可验证的已上传状态且所有必要文件均满足时显示上传确认；否则显示待上传或状态未知。即使本机上传确认，也不声称 Mac 已下载。跨设备可能先收到指针再收到媒体，读取说明要求下载完整并核验后再分析。[iCloud 文档与占位文件](https://developer.apple.com/library/archive/documentation/General/Conceptual/iCloudDesignGuide/Chapters/DesigningForDocumentsIniCloud.html)。

备选：双向文件合并需要解决多写者、删除传播和冲突，超出当前个人 iPhone 记录、Mac 读取的目标。单向快照保留清晰事实来源；从外部恢复统一走显式导入。

### 9. 验证分层与完成口径

纯领域测试覆盖数值、日期、资料版本、已记全失效和复制规则；存储测试使用真实临时磁盘，注入提交失败、图片损坏、中断和迁移错误；直连适配器测试验证密钥隔离、固定端点、请求边界和模型异常，既有服务契约测试继续覆盖可选服务；原生 UI 测试跑完整用户流程。

真机验收独立覆盖相机／HEIC、权限、键盘、辅助字号、VoiceOver、离线重启、iCloud 撤权和 iPhone→Mac 完整资料到达。真实模型使用用户明确选定的测试图片完成一轮识别、修正、导出；测试替身通过不能替代真实接口验收。日志及仓库只保存脱敏验收结论，不保存用户身体资料、照片或密钥。

## Risks / Trade-offs

- 照片与数据库不共用事务 → 暂存、稳定文件、数据库提交和引用清理分阶段，针对中断点测试。
- SwiftData 迁移或影子库激活失败 → 保留旧库，原子活动指针切换，启动时识别未完成迁移；不静默重建空库。
- iOS 后台执行和 iCloud 上传不可保证即时 → 本地操作独立，持久 dirty／任务状态，前台续做，状态文案仅描述可观察事实。
- 模型份量判断和营养估算可能偏差较大 → 展示假设及来源、提供逐项人工修正，不以数值校验冒充营养真实性验证。
- 供应商是否已处理超时调用不可知 → 终结为结果未知，不自动重复收费调用，用户显式重试。
- 大量照片与不可变备份增长 → 缩略图独立、导入导出限额和分批处理、显示空间错误；首版保留备份历史，后续可单独设计清理策略。
- 像素字体在大字号或辅助功能下可读性不足 → 布局重排、后备字体、系统语义与真机核验优先于像素尺寸完全复刻。
- 原型中演示与真实内容可能混合 → 迁移预览、来源标识、默认排除已知演示内容，不假定所有历史热量来自真实模型。

## Migration Plan

1. 新增独立原生工程和版本化空库，以隔离演示验证页面，不改写现有浏览器存储。
2. 完成全部本地功能及公式／存储测试，再开放旧 JSON 导入预览；保留原导出文件，失败可重新导入。
3. 在 iPhone 本机配置千问 API Key，确认发送范围与费用后，使用明确指定的测试图片完成真实联调；私有服务可选，不作为交付前提。
4. 启用系统目录选择和资料包发布，在用户自己的 iCloud Drive 中验证离线、权限、部分下载和 Mac 完整读取。
5. 使用提供的签名将 App 安装到用户 iPhone，完成三个阶段所有验收后交付。开发签名、测试分发及有效期限按所提供账号能力记录，不假设已拥有特定开发者权限。

回退：代码可回退到上一工作版本；数据升级前保留的旧库供旧版本使用，不让旧代码读取未知的新 schema。断开千问或删除本机密钥不影响本地记录和人工热量；断开目录不删除本地或云端既有资料。结果未知的直连任务不因重启再次执行。
