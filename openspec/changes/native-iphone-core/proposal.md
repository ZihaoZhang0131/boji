# 原生 iPhone 核心功能提案

## Why

薄记目前是可交互的网页原型，已有饮食、训练和热量计算规则，但记录依赖浏览器存储，食物 AI 与 iCloud 仍是演示。需要以现有页面为蓝图，完成个人自用的原生 iPhone App，让记录可靠落盘、照片得到真实估算，并可将完整资料带到 Mac 复盘。

## What Changes

- 原生重建「记录／回顾／我的」及相关表单，保留黑白像素风、真实照片、中文交互与轻量记录流程；使用真实日期时间，首次使用从空资料开始。
- 建立本地数据库、独立照片存储、可恢复草稿、明确的保存失败反馈和版本迁移机制，离线也能记录和回顾。
- 完成饮食的拍照／相册、多图、备注、餐次、标签、补记、编辑、删除与恢复。
- 完成负重／自重训练、逐组确认、复制、批量补记、草稿恢复；补齐训练修改、删除与恢复。
- 完成个人信息历史、阶段目标、代谢与运动净消耗快照，以及时间线、日历、照片搜索、训练历史和 7／30 天热量回顾。
- iPhone 在用户授权后直连千问进行真实食物识别：模型密钥仅存本机 Keychain，支持自动估算偏好、离线待处理、明确重试、份量修正、结果版本校验与来源追溯；人工修正优先，无需个人自建服务器。
- 提供含结构化数据和独立照片的版本化资料包，支持恢复、重复导入去重与旧原型 JSON 迁移。
- 经用户选择 iCloud Drive 目录后更新备份资料，区分本机保存、目录写入和系统上传状态；Mac 上的 Agent 通过资料包和复盘说明读取记录。
- 将完整功能拆为「原生记录」「真实 AI」「资料流转与真机验收」三个交付阶段，全部完成后才视为本变更交付。

范围边界：本次面向个人自用，Mac 是资料读取端；不增加原生 Mac App、多人账号产品、订阅、应用内 AI 聊天、HealthKit 或 CloudKit 多端数据库同步。辅助重量、热身组、计时／有氧专用表单仅在旧说明中出现，缺少完整 PRD，保留为待确认扩展，不作为本次既定验收项。现有网页原型保留为参考与旧数据导出入口。

## Capabilities

### New Capabilities

- `native-app-shell`：原生导航、像素视觉、真实时间、系统交互与可访问性。
- `local-record-storage`：离线持久化、照片生命周期、草稿、回收站与数据迁移。
- `meal-recording`：饮食录入、照片、补记、编辑与删除恢复。
- `workout-recording`：训练动作与完成组、复制补记、草稿及历史修改。
- `profile-and-goals`：身体资料版本、阶段目标及历史。
- `energy-and-review`：确定性的热量计算、历史快照、完整度规则与各类回顾。
- `food-estimation`：真实食物识别、本机密钥和授权管理、任务版本管理、人工修正；已有私有服务可选。
- `data-portability`：资料包、导入恢复、旧数据迁移、iCloud Drive 备份及 Mac Agent 交付。

### Modified Capabilities

无。项目目前没有主规格，以上能力均建立新规格。

## Impact

- 实施已新增 `ios/` 原生工程及 `services/food-estimation/` 私有识别服务；个人版改由 iPhone 直接连接千问，服务保留为可选适配器，不再是交付前提。
- `app.js`、`redesign.js`、`energy.js`、`pixel.js`、现有设计说明及验证脚本是行为参考；网页截图和素材是视觉参考，不直接作为原生运行时代码。
- 原生依赖 SwiftUI、SwiftData、系统相机／照片选择器、Keychain、文件选择器与文件协调；千问调用使用固定 HTTPS 端点和本机任务状态，模型账户金额预算由用户在供应商侧设置。
- 新增千问图片与估算请求适配、资料包格式及旧版 JSON 转换契约。原型数据通过显式导入迁移，不自动读取浏览器资料。
- 真机、iCloud 和真实模型验收需要用户可用的 Apple 签名、iCloud Drive、本人在手机配置的千问密钥及指定测试图片；不要求私有服务地址。
